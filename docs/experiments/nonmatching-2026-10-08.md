# 2026-10-08：非匹配阶段优化

本阶段基线是 [区间位图与增广游标](algorithm-2026-10-08.md) 完成后的工作区快照，不是 `81f4a43`；下表只衡量后续非匹配改动的增量收益。匹配搜索仍使用原 HKDW，邻接排序和最终配对选择保持一致。

## 落地改动与上界

- 混合 LOD 叶子只写入起始行／列事件，通过起止事件更新活动区间。稳定行共享区间，并在 chord 提取和矩形输出中跳过稳定行带。单方向活动快照量 `Q≤Σside≤n²`，轴构造为 `O(L+n+Q)`。全单位像素保留直接桶枚举路径，避免到期状态开销，为 `O(L+n)`。
- Builder 保存未展开 leaves，追加摊还 `O(1)`，finish 使用相同事件后端；取消扩展行列列表及比较排序，仍返回拥有型矩形 Vec。
- Image 记录由 24 字节缩为 8 字节，Morton 终点从 LOD 推出。有序输入跳过排序，至多 64 条用比较排序，大乱序输入用有限键表和原地置换，为 `O(L+n²)`；额外固定栈数组为 16 KiB，无第二个堆 Vec。
- 冲突图改为 start／query／end 单趟 x 扫线，活动 y 位图直接枚举冲突，不再逐格展开水平 chord。事件链复用 CSR 临时存储，CSR 统计左度数时同时记录右边段实际起点。64×64 下为 `O(n+C+E)`；推广多字位图时还需计入范围查询，总体仍为二次上界。
- 竖直切线采用端点 XOR 和前缀 XOR，取消逐行展开。切线构造为 `O(n+C)`；分区仅处理行布局及切线的变化边界，上界仍为 `O(n²+C+R)`。

完整精确分解仍为 `O(n³)`，空间为 `O(n²)`。借用分解及 scratch 初始化仍零堆分配，无 unsafe、无运行时依赖。x86_64 scratch 对象从 334,912 降为 326,336 字节（约 319 KiB），减少 8,576 字节。

## 测量方法

Windows x86_64，`rustc 1.100.0-nightly (67eda617e 2026-09-10)`，默认 release 配置。两份库编入同一进程，固定在逻辑 CPU 2，每阶段连续调用 64 次，以 ABBA／BAAB 顺序交替；每组 41 轮，两次完整重复。输入、预构造 image 和 scratch 均在计时外准备。

`leaves`／`image` 是复用 scratch 的完整借用分解；`prepare_image` 含 Image 校验、分配与排序；`builder_layer` 每次 clear 后 push 全部 leaves 再 finish，复用 Builder 容量，包含拥有型输出复制。计时前检查入口结果数量一致。百分比为各轮 `(新/旧-1)` 的中位数，负值表示更快，斜线分隔两次重复；不同列和输入的百分比不能相加。

大 LOD、规则块、混合行带、条纹和稠密长 chord 的借用分解收益可复现。第二次中位耗时分别为：大 LOD leaves 1.091→0.208 µs，规则块 5.914→1.300 µs，混合行带 1.719→0.364 µs，条纹 40.946→23.972 µs，稠密边框 image 50.210→43.693 µs。大乱序 Image 构造以及全部输入的 Builder 整层构建收益清晰。

不把这些结果写成普遍加速：最大 chord 孔洞 leaves 稳定增加约 4–6%（第二次 76.412→80.853 µs，中间 50% 成对变化为 +0.90% 至 +6.09%）；稀疏随机 leaves 增加约 3–4%，双色棋盘格约 3%，密集随机 leaves 约 6%。原含孔图、多颜色组和逆序像素的借用入口波动跨过零，不能声称稳定改善。保留新结构的依据是压缩输入、构建入口和长 chord 的显著收益、二次非匹配上界及较小 scratch；像素密集短 chord 工作负载存在上述代价。

早期候选统一维护到期事件，导致单位像素回退，现已保留单位像素直接路径。两层 MSD 原地排序较慢，已换成有限键表置换。冲突扫线曾做两趟并依赖 count_ones，现用一趟边枚举，避免重复事件维护。这些早期版本的数字不用于最终表格。

## 复跑与验证

本地配对程序和原始 CSV 位于忽略目录 `target/nonmatching-comparison/`（最终为 `paired-run-3.csv`、`paired-run-4.csv`）。保留该目录时可复跑：

```powershell
cargo build --release --manifest-path target/nonmatching-comparison/Cargo.toml --target-dir target/nonmatching-comparison/build
[System.Diagnostics.Process]::GetCurrentProcess().ProcessorAffinity=[IntPtr]4
./target/nonmatching-comparison/build/release/nonmatching-comparison.exe
```

仓库长期维护的入口为 `cargo bench --bench worst_case`：原低差异含孔图、十一类确定性代表输入、四种调用方式和 scratch 初始化。比较提交时，应两边使用相同新增输入、相同编译参数，并交替测量完整调用。

`cargo test --all-features`、`cargo test --release --no-default-features` 各通过 50 项单元测试、1 项混合 LOD 集成测试和 5 项资源测试。Clippy（全部 target／feature，warnings 为错误）、fmt、diff 检查通过。新增验证覆盖 128 个随机四叉树层与独立单位像素展开、所有 Morton 键及 63／64／65 排序阈值、闭端点冲突、乱序右边段、有序 CSR 与最终配对一致、相邻 cut 及终点 64、失败后复用。保留独立穷举最优性 oracle、零分配和四个 2 MiB 栈 worker 测试。

真实锯齿边框测试产生 `H=V=122`、`E=3964`，其中包含 `K₆₁,₆₁` 核心，提醒 `E≤(n−1)²` 不能进一步推出 `E=O(C)`；该输入预热已取得完美匹配，HKDW 为零轮。后续优化仍需看实际搜索行为。
