# 2026-10-08：默认 no_std／no_alloc

基线为 `3998455`。当前默认 features 为空，库始终声明 `#![no_std]`；默认生产代码不导入 `std` 或 `alloc`。没有改变矩形分解算法、512-bit SIMD 宽度、容量上界、scratch 布局与 O(n³) 保证。

## Feature 与接口

| 配置 | 依赖 | 可用接口 |
| --- | --- | --- |
| 默认／无 feature | core | leaves／labels 的 borrowed、sink、packed 六个入口及固定容量类型 |
| alloc | core＋alloc | 另提供 SparseQuadImage64、SparseLayerBuilder64、Vec 拥有输出 |
| std | core＋alloc＋std | 包含 alloc；保留宿主 abort 语义 |
| profile | std | 另提供 std::time::Instant 阶段计时 |

SIMD 移为 `core::simd`，std 原先对此重新导出，逻辑宽度仍为512 bit。数值、切片、范围、swap等设施改用core；Vec所有者与Morton拥有输入构造辅助函数仅在alloc下编译，普通borrowed不计算Morton键。

内部不变量失败默认调用安全的 `core::process::abort_immediate`，std feature使用 `std::process::abort`；两者不展开栈。普通非法输入及sink失败继续用Result返回。库没有panic handler；普通panic／debug assertion由最终程序的handler处理。abort_immediate在多数目标降为trap，具体行为依架构；不能把它等同于所有平台上的C abort或panic handler。

当前需要nightly的portable_simd及abort_immediate，验证工具链Rust1.100.0-nightly（67eda617e，2026-09-10）。未增加第三方运行时依赖或unsafe库代码。默认scratch仍为264256 B，输入／输出对象仍按原方式复用。

## 真实无分配器链接检查

[checks/no_std_link](../../checks/no_std_link/) 是独立的 `#![no_std]`／`#![no_main]` 调用程序，依赖显式关闭default-features；提供自己的入口与panic handler，没有global allocator。调用全部六个核心分解接口，并将实际标签／输出传给black_box。

在x86_64-unknown-none上release链接成功，目标rlib仅有本库、core与compiler_builtins，没有std或alloc。compiler-builtins-mem为裸机提供memcpy／memset等内存原语。验证只构建和链接，**没有在裸机执行**；固件启动、栈、CPU初始化及异常处理仍由最终程序负责。

```sh
cargo -Z build-std=core -Z build-std-features=compiler-builtins-mem build --release --target x86_64-unknown-none --manifest-path checks/no_std_link/Cargo.toml --target-dir target/no-std-link
cargo check --lib --no-default-features --target wasm32-unknown-unknown
```

前者需要nightly及rust-src，本机已安装；后者需要相应已安装target。链接fixture使用panic=abort。库本身不强制调用程序的panic策略。

## 回归测试

默认core-only运行63项（48 unit＋15 integration）；alloc／all-features运行原71项。核心oracle、随机LOD、SIMD接缝、65535标签、最大4096输出、自动阈值、错误恢复、sink前缀和零分配计数继续在默认模式运行。仅Image／Builder专属测试受alloc门控；测试程序自身允许使用宿主std，不把这个当作裸机证明。

default release、alloc-only release、all-features debug、两个配置的all-targets Clippy（-D warnings）、wasm编译检查和裸机链接均通过。Criterion dry run现在显式启用alloc。Cargo已有manual_readme提示与build-std core的future-incompat提示不是库新引入的源码错误。

## 完整调用性能

同一进程编入两份库，基线为3998455原std实现，候选为默认core-only。默认release、相同工具链和ISA，固定逻辑CPU2；12个相同代表输入，leaves／native grid／相同bounds+label checksum sink三个入口。两个库的完整有序Rectangle序列在计时外对照，已知最优数另查；scratch及输入均在计时外准备。每阶段64次、41轮ABBA／BAAB，两次独立重复，无重叠编译或采样。

不能宣称移植完全没有性能回退：低差异孔洞native grid两次为+6.77%／+6.52%，IQR分别[2.75,8.85]%／[2.83,9.64]%，约65→68–70 µs；leaves sink也回退约4–5%。密集随机native grid两次约−11%／−10%，最大chord约0–1%。具体指令级原因未定位；feature门控、终止路径和crate代码生成会变化，算法工作量及内存布局没有增加。

试过静态core panic和强制内联终止wrapper；没有得到全面收益。最终使用隔离的cold abort路径，保持原先不展开栈的内部失败语义，接受并明确记录当前局部回退，未为一个输入添加图形特判。调用方若需要旧拥有型API，应启用alloc；阶段计时启用profile。

## 复现

从仓库根目录用 `git archive 3998455` 导出到忽略目录 `target/nostd-before`，将其Cargo.toml包名改为 `rectangle_decomposition_nostd_before`。已准备好的baseline无需覆盖。支持程序共用上一轮固定case生成器。

```powershell
cargo build --release --manifest-path docs/experiments/support/no-std/Cargo.toml --target-dir target/nostd-reproduction
[System.Diagnostics.Process]::GetCurrentProcess().ProcessorAffinity = [IntPtr]4
& target/nostd-reproduction/release/nostd-comparison.exe
```

这是host性能对照，不能外推为未执行的裸机或WASM性能。默认无feature、alloc、std、profile的功能分层应继续独立检查。
