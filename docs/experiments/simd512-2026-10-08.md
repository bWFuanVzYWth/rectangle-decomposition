# 2026-10-08：512-bit portable SIMD 实验

基线为非匹配优化提交 `208ad0d`，最终候选仅改变 Image 构造的 Morton 编码路径，使用 nightly `std::simd`。用户指定所有显式 SIMD 数据向量统一为逻辑 512 bit；本次机器支持 AVX2、不支持 AVX-512。库仍禁止 unsafe，未引入第三方运行时依赖。

## 最终实现与保证

至少 64 个 leaves 时，将输入分为最多 64 个叶子的块，再以 32 个叶子构造两份 u16 坐标 staging。`u16x32` 对应 512-bit 数据向量，执行两坐标的位展开和交错；尾部补零，仅写回真实叶子的键。随后按原输入顺序检查 shape、写入紧凑记录和检测有序状态。少于 64 个叶子保留原标量计算。

预计算只依赖两个完整 u8 坐标，最多生成 16-bit Morton 键，不依赖未验证的 LOD。首个 shape 错误以及 shape 先于 overlap 的拥有型 Image 语义不变；验证成功后键仍在 12-bit 范围内，有限键排序的容量条件保持。

所有批量操作为 `O(L)`，Image 构造仍为 `O(L+n²)`，精确分解仍为 `O(n³)`、空间为 `O(n²)`。源级 staging 为输出 u16[64]、两份坐标 u16[32] 和 keys u16[32]，共约 320 字节，实际栈峰值由编译器决定。scratch 没有新字段，仍为 326,336 字节。普通 borrowed leaves 与 Builder 不计算 Morton 键，已经构造的 Image 在借用分解时也不重复计算。

`std::simd` 当前仍是 [nightly experimental API](https://doc.rust-lang.org/std/simd/index.html)，因此主库启用 `#![feature(portable_simd)]`，需要 nightly 工具链。逻辑 512 bit 并不要求 512-bit 硬件寄存器，编译器可将运算拆为目标支持的指令。

## 生成代码核对

实际构造函数的汇编／IR 使用 Rust `1.100.0-nightly (67eda617e 2026-09-10)`、LLVM `23.1.1`，Windows x86_64。Morton 位运算在 IR 中为 `<32 x i16>`；默认目标拆成 4 路 XMM，`-C target-feature=+avx2` 拆成 2 路 YMM，没有使用 ZMM。两种代码均含 staging 填充、清零和 keys 写回，这些成本都计入完整构造测量。

本地证据保存在 `target/simd-analysis/explicit512-default/` 与 `explicit512-avx2/`。默认 `.s` 的 7215 行附近和 AVX2 的 8204 行附近是 Morton 位运算；IR 相应为 7976 和 8268 行附近。它们来自仅含 Morton 改动的隔离库，不是只看独立微内核。

之前的自动向量原型也已命中 SIMD：默认每次 8 个 leaf，AVX2 每次 16 个 leaf。它的部分构造测量比显式 512-bit 更快，说明更宽的逻辑向量并不自动降低常数。宽度、数据整理和生成代码必须一起量测；[LLVM vectorizer 文档](https://llvm.org/docs/Vectorizers.html)也说明向量化使用成本模型，非连续 gather/scatter 未必划算。

## 最终配对测量

两份库编入同一进程，逻辑 CPU 2，release。同一组内基线和候选使用完全相同的 ISA 选项；默认与 AVX2 组分别构建，不把两组绝对时间直接相减。每阶段连续调用 64 次，以 ABBA／BAAB 交替，构造入口 81 轮、构造后立即借用分解 41 轮，各完整重复两次。scratch 在计时外构造并复用，构造入口包含分配、校验、排序及析构；pipeline 另外包含完整借用分解。

## 未保留的尝试与后续边界

- 右度数最大值用 u8x64 归约，最终距离等于 MAX 的标记用 u16x32 比较，两者都是 512-bit 数据向量，保持 `O(C)`。默认及 AVX2 的完整调用未显示稳定整体收益，原连续循环已有自动向量化，且覆盖标记只在终局的一种分支执行，因此撤回显式版本。
- 单份 u16[32] staging 把 u/v 打包为 `u | v<<8`，再用 512-bit 向量分离坐标。LLVM 确实合并为 word 读取，但仍要计入额外 AND/shift；相对双 staging 的一次配对中，默认逆序输入回退约 9%、AVX2 稀疏随机回退约 8%，其它局部收益多为 1–4%，未采用。
- 标量位图的 u64 AND、置位枚举、POPCNT/TZCNT 等已经处理多个格点，但它们不是 SIMD 指令。不能把 native 编译带来的标量指令收益归为 SIMD。
- matching 的邻接读取、配对间接访问和队列／DFS 状态变化仍具有数据依赖。不能为了宽 SIMD 改成无条件 `C×C` 位图扫描；稀疏图的每轮成本可能由 `O(C+E)` 放大为 `O(C²/w)`。若探索混合表示，仅对度数 `d≥ceil(V/w)` 的行建立位图，可让位图扫描和额外存储受 `O(E)` 约束；这只说明复杂度可守住，并未证明实际更快。

对当前实现，算法减少稳定行、LOD 展开和排序工作所带来的完整调用收益远大于本次 SIMD 增量。局部 SIMD 可保持上界，但未找到无需改变搜索结构就能普遍大幅加速借用分解的证据。

## 复跑与验证

最终本地配对程序和八份 CSV 在 `target/simd512-final-comparison/`。保留忽略目录时可复跑：

```powershell
cargo build --release --manifest-path target/simd512-final-comparison/Cargo.toml --target-dir target/simd512-final-comparison/build
[System.Diagnostics.Process]::GetCurrentProcess().ProcessorAffinity=[IntPtr]4
./target/simd512-final-comparison/build/release/simd512-final-comparison.exe
./target/simd512-final-comparison/build/release/simd512-final-comparison.exe --pipeline
```

AVX2 组使用 `RUSTFLAGS=-C target-feature=+avx2` 和独立 target-dir；只能在支持 AVX2 的机器上执行。未为当前机器启用 AVX-512。长期基准 `cargo bench --bench worst_case` 新增 `construct_and_decompose`，可直接观察局部构造收益对完整 pipeline 的影响。

最终验证为 debug 全 feature、release 无默认 feature 各 50 单元＋9 集成测试（59 项），以及 AVX2 release 测试、全部 target／feature 的 Clippy、fmt 和 diff 检查。新增测试覆盖 31／32／33、63／64／65、95／96／97、127／128／129 及满图长度、顺逆序和 shape 错误跨块；原全部 Morton 坐标与位交错 oracle、精确分区及匹配最优性证书、零分配和四个 2 MiB worker 栈测试仍通过。
