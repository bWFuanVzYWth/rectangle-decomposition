# 优化审计与精简

2026-09-10。比较基线为上一轮区间端点优化后的工作区（在 `00edda2` 栈版本上继续优化），
不是最初的堆版本。采用删除实验：独立移除候选优化，再测完整分解及组合后的结果。

## 删除与保留

| 候选 | 依据与决定 |
| --- | --- |
| 收集切线后的两次排序 | 后续仅按 OR 合入位图，顺序不影响结果。删除，避免无用排序。 |
| chord 排序前手工检查是否有序 | 删除后未呈现稳定回退，直接调用标准排序，保持原排序键。 |
| 逐格点有效标记数组 | 只用于调试断言，却在 release 中维护；列标记和列内位图已表达相同信息。删除，以原有位图检查重复格点。 |
| 预校验 image 的独立事件扫描 | 需要两份 8192 容量事件数组、活跃集合及反复排序。改用 leaves 已有的行桶路径，两个入口共用实现。 |
| 重复的容量检查 helper | `reserve_more` 与 `reserve_exact` 在固定容量实现中完全相同，合并；移除事件扫描不再使用的 `swap_remove`。 |
| 每轮清空列位图，连列标记也删除 | 独立试验在 441 个小颜色组上约从 84.2 增至 86.9 μs。保留列标记，避免对每个颜色组清空全部列。 |
| 度 1 贪心和长度 3 预热 | 分别删除后，低差异孔洞样本约从 120.5 增至 125.1、127.3 μs。保留现有匹配策略。 |

本轮生产源文件净减少约 220 行。公开入口和错误类型不变；`sort_cuts` profiling 字段为兼容保留，
值始终为零。未改变匹配策略、颜色分组、含孔处理、整体 O(n³) 时间或 O(n²) 空间上界。

## 完整分解

i9-14900KF、Windows x86_64、rustc 1.99.0-nightly（14cae6813），`-O -C target-cpu=native`。
两版在同一进程、同一逻辑核上轮换顺序。最终确认每类 16 张图、11 轮各至少 50 ms，
表中为每轮平均耗时的中位数，单位 μs。预先构造 quad 输入和预校验 image，复用 scratch；
计时不含输入构造、scratch 初始化或输出复制。

预校验 image 入口的收益在多轮删除实验及组合验证中复现。原始 leaves 入口并非全面加速：
若干模式约慢 2%～3%，单像素约增加 27 ns；密集单色和极限孔洞分别约快 8%、22%。
保留这次精简的依据是删除整套重复实现、固定空间减少 22%，以及 image 入口的明显收益。
一次较短采样中稀疏随机图出现过 15% 左右回退；延长采样后为约 3%，未据此前者继续增加特殊分支。

本地实验脚本、源码快照及原始数据位于 `target/simplify/`，属于可清理的忽略产物：
`ablate.py`、`compare_base_current_confirm.csv`、对应 `.txt`、`measure_init.py` 和 `init.csv`。
这些结果不是跨硬件的性能保证，体素引擎中的多线程分配器竞争仍需在调用方测量。

## 校验

- 6,368 张图：224 张模式图、2,048 张不同密度／颜色数随机图、4,096 张穷举 4×3 二值图。
- 每张图使用像素叶子和 quad 两种表示，分别调用 leaves 和预校验 image 入口；两版有序矩形列表逐项相同。
- 独立检查像素颜色、完整覆盖和无重叠；两个入口各 224 次复用调用均为零分配。
- 34 个单元测试和 5 个资源集成测试通过 debug/all-features 与 release/no-default-features。
- 保留 6,561 种局部像素凹角对照、65,536 个二分图穷举、容量上限和标记回绕检查。
- 新增两个入口混合复用 scratch 的零分配测试；4 个并发 worker 各 2 MiB 栈的资源测试继续通过。
- Clippy（全部 target/feature，警告作为错误）、stable 编译检查和格式检查通过。
