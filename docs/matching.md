## 1. 用最大同色区间表达像素

直接 leaves、预校验 image 和 builder 共用起点事件桶。每个叶子仅在起始行、起始列各写入一个区间；桶以区间起点索引槽位，用一个 `u64` 标记有效起点。对于混合 LOD，扫描到叶子的起止事件时更新活动区间，按最低置位递增枚举、检查重叠并合并相邻同色区间；事件之间的行列共享同一 `LineRange`。正方形区间的长度同时给出其沿扫描方向的存活行数，终点 64 由最终输出处理。

全单位像素输入的每个起点桶已经是该行的完整布局，直接枚举，无需维护活动区间及到期事件；与上一行合并结果相同则共享区间。两条路径均无比较排序。令 `Q` 为单方向事件行上的活动区间快照总量、`S=Σside`，有 `Q≤S≤n²`。在当前单字位图实现中，单轴构造为 `O(L+n+Q)`，单位像素路径为 `O(L+n)`；推广多字位图时须计入分块成本。profile 仍按所有像素行求和统计逻辑区间数，共享存储不改变字段含义。

同一起点再次写入，或与尚未到期的同起点区间同时活动，直接报告重叠；不同起点的包含或部分重叠，仍需在有序枚举时比较前一区间的终点。只有本轮位图置位的槽允许读取，重复调用重置桶位图和事件状态。行方向已检查所有叶子的面积重叠，列方向无需再次检查区间终点。

增量 builder 仅保存已校验形状的 leaves，追加为摊还 `O(1)`，finish 使用同一后端，不展开或排序行列列表。拥有型 image 将每个已校验叶子存为 8 字节记录（leaf 与 12-bit Morton 起点），终点由 LOD 推出。有序输入跳过排序；至多 64 个记录使用比较排序，大乱序输入用两个 4096 项 u16 表构造原地置换，成本 `O(L+4096)`，不另分配叶子数组。所有入口送给提取器的区间都有序、无重叠且已最大化同色区间。

对相邻两行的区间 `a`、`b`，记 `start = max(a.start, b.start)`、`end = min(a.end, b.end)`。它们产生水平 chord 的条件就是：

```text
a.value == b.value
start < end
a.start != b.start
a.end   != b.end
```

例如上行 `[0,3)`、下行 `[1,4)` 同色，交集 `[1,3)` 两端都是凹角。起点不同意味着交集左侧只有一行继续同色；另一行不能继续，否则区间就不是最大区间。终点同理。这省去了重新查询邻近像素的工作，竖直方向完全对称。

两方向共用 `emit_chords_for_boundary` 双指针扫描，跳过布局稳定的边界。较早结束的区间向前推进；终点相同时两边同时推进。水平、竖直列表直接保留提取顺序，无需按标签排序，也不保存颜色组范围。

**不能省略的条件：**最大化同色区间是端点判定正确的前提。若改变输入规范化逻辑，必须重新验证这一前提。

## 2. 在整数格点上建立冲突图

所有颜色一次建图。[全局图的依据](algorithm.md)是不同标签的 chord 不可能相交；同向 chord 的格点占用在全图内也互不重叠。只有一个方向有 chord 时，全部候选都可保留，直接跳过建图和匹配；两侧都有候选但构图后没有冲突边时，也全部保留并跳过匹配。

两个方向都有候选时，将水平 chord 的起止 x 和竖直 chord 的查询 x 写入固定事件桶。按 x 扫描，以一个 y 位图和每行的 chord 编号维护活动水平线段；竖直 chord 与活动位图的 y 范围取交，枚举置位得到冲突。相同 x 按 start、query、end 处理，保持闭线段端点冲突。

每次清空事件头并从空活动位图开始，只有置位的 y 才允许读取编号。无需编号网格、轮次标记或逐格展开长 chord。事件链复用 `right_layout`，在 64×64 的单字位图范围内，扫线成本为 `O(n+C+E)`。

CSR（Compressed Sparse Row）用两个连续数组保存邻接表：顶点 `h` 的邻居位于 `edges[offsets[h]..offsets[h+1]]`。这样遍历时无需为每个顶点单独分配容器。

单趟扫线将每个竖直查询的全部边连续写入缓冲，同一右顶点只有一个边段，段内按 y 递增；右顶点的段顺序可以随 x 事件变化。统计左度数的同一遍边扫描记录每段实际起点，再按 `(右度数, 右编号)` 稳定计数排序右顶点，散布到左 CSR。邻接顺序及匹配选择与旧构图一致；无需第二趟扫线或逐邻接表比较排序。

**必须保持：**每个右顶点的边连续且只有一段；每个活动 y 至多一条水平 chord；右度数不超过 `n−1`。

## 3. 用预热减少搜索，用 HKDW 保证最优

匹配先进行三项便宜的预热：优先匹配左侧度为 1 的顶点、按右度数顺序贪心匹配、尝试长度为 3 的增广路径。预热阶段同时构建转置 CSR，供后续反向遍历复用。这里的度 1 处理是一次预热扫描，不是完整的递归消除算法。

长度 3 搜索为每个匹配左顶点保存单调邻接游标。长度 1／3 增广只消耗空闲右顶点，已匹配右顶点始终保持匹配；因此检查过的不可用邻居和刚选中的邻居，以后都不会成为新的空闲候选。游标可直接越过这些边，使内层所有搜索合计至多扫描 `E` 条边，整个预热为 `O(C+E+n)`，并保持原先的配对选择顺序。游标复用转置构造已用完的 `write_offsets`，每次重新初始化；这一单调性仅用于预热，不能直接推广到 HKDW 搜索。

增广路径在未匹配边与匹配边之间交替，两端均未匹配；翻转路径上的配对，会使匹配大小增加 1。预热只决定从哪个初始匹配开始，精确结果仍由后续搜索完成。

HKDW 是 Hopcroft–Karp 的 Duff–Wiberg 变体。其依据见 [Duff、Kaya、Uçar 的说明，第 3.3.2 节](https://epubs.stfc.ac.uk/manifestation/5901)。本实现每轮执行：

1. 从全部未匹配竖直顶点反向 BFS，找到距未匹配水平顶点最近的层次。
2. 从最短层上的未匹配水平顶点出发，沿层次约束 DFS，得到极大的一组顶点不相交最短增广路径。
3. 从剩余未匹配水平顶点追加 DFS，寻找更多本轮不相交路径，不再限制为最短长度。

两段 DFS 共用本轮访问标记，成功或失败搜索访问过的左顶点都不再展开；下一轮清除标记。这样追加搜索不会把每轮工作放大成对每个根重复扫描全图。队列和 DFS 都使用显式固定数组，不依赖递归栈。

匹配结束后采用 [从右侧出发的对称独立集公式](algorithm.md)。如果还有未匹配水平顶点，最后一次反向 BFS 必然失败；这一轮没有最短深度截断，`right_distance` 完整记录从空闲竖直顶点出发的交替可达性。根据配对数组即可标记可达水平顶点，保留不可达水平 chord 和可达竖直 chord。收尾只扫描顶点数组，成本为 `O(C)`，无需再做一次图遍历。

如果水平侧已全部匹配，则全部竖直 chord 就是最大独立集，直接采用这个结果。此时可能没有执行失败 BFS，上一成功轮的距离不能作为完整可达集使用。`reachable_left`、`reachable_right` 两个内部字段在收尾阶段保存“水平选中、竖直排除”标记，而非同一起点下的一对可达集。

## 4. 用切线位图驱动矩形扫描

水平切线用 OR 合入行位图。竖直切线在起止行 XOR 相应 x 位，前缀 XOR 得到逐行活动位图；同 x 的切线没有面积重叠，邻接段的终止和启动相消也正确。切线无需排序，构造成本为 `O(n+C)`。

`build_runs_for_row` 在竖直切线处分割同色区间；`merge_sparse_runs` 用双指针比较活跃矩形和新 run。扫描只处理行布局、水平切线和竖直切线起止事件之间的边界，稳定行带直接延长高度。只有标签、横向范围完全一致且没有水平切线阻挡时，矩形才继续延伸；其余矩形结束或新建。

`ActiveRect::match_key` 把标签和横向端点打包为整数比较键；起始行不参与匹配。两套活跃矩形数组通过交换引用交替使用，避免逐行复制整块内联数组。

## 5. 保持实现简洁的边界

这些优化依赖本问题的稳定条件：整数坐标、固定边长、最大同色区间、同向 chord 不相交和明确的容量上界。更改任何前提时，应同时复核 [资源上界](scratch.md) 和 [复杂度推导](research.md)。

`profile.chord_groups` 仍表示至少有一条 chord 的不同标签数，使用临时标签位集计数；普通分解路径不做这项计数。`matching_phases` 表示全局 HKDW 批次次数，不能与旧版逐颜色批次数之和直接比较。全局求解也不保证所有输入都更快：小分量可能受最难分量的轮数影响，应测量完整调用。

不要把“某种输入更快”写成普遍保证。工程改动用完整分解测量：收益明显且可复现时保留；难以区别于噪声时优先选择较简洁的实现。测量记录属于实验或提交说明，正文只保留现有结构的理由和不变量。
