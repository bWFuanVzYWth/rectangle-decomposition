# 固定容量栈 scratch

`SparseOptimalScratch64` 的所有内部缓冲都存放在对象内，没有 `Vec`、`Box`、指向自有堆缓冲的
指针或未初始化元素。内部 `FixedVec<T, N>` 使用 `[T; N] + len`，只接受 `Copy` 元素。
初始化、`decompose_borrowed`、`decompose_quads_borrowed` 和销毁不调用堆分配器。
库代码保持 `unsafe_code = "deny"`，没有第三方运行时依赖。

## 使用和兼容性

每个 worker 在任务循环外调用一次 `SparseOptimalScratch64::new()`，随后传递 `&mut` 复用。
`clear()` 只重置有效长度；算法按需重置距离、配对和访问标记，不在每张图开始时清零整个对象。
行扫描的两个活跃矩形缓冲通过交换引用交替使用，不逐行交换内联数组内容。

- `new()`、`Default::default()`：直接创建可用的固定容量缓存。
- `preallocate_64()`：保留原签名，始终返回 `Ok(())`，不修改当前数据。
- `try_new_preallocated()`：保留原签名，返回 `Ok(new())`；新代码优先使用 `new()`。
- 返回 `Vec<Rectangle>` 的便捷方法仍复制、分配输出；输入 image 和 builder 仍有独立的拥有型容器。
- 借用输出位于 scratch 内部，必须在下一次可变使用前消费完毕。

## 容量依据

对合法、互不重叠的 64×64 彩色像素输入，以下上界不要求颜色区域连通，也包含孔洞。

| 缓冲类型 | 容量 |
| --- | ---: |
| 每方向轴事件 | 8192 |
| 每方向轴区间 | 4096 |
| 每行区间、run、活跃矩形 | 64 |
| 每方向 chord、配对、队列、DFS 栈 | 1953 |
| 有 chord 的颜色组 | 1024 |
| 冲突边、CSR 边、可重复的最短层根 | 3969 |
| 输出矩形 | 4096 |

每个内部格点最多是一个颜色的凹角；该凹角在同一轴上只支持一个延伸方向，因此不会成为
两条同向 chord 的端点。每条内部格线只有 63 个候选端点，每条 chord 消耗两个不同端点，
故每方向至多 `63 * floor(63 / 2) = 1953` 条。把横纵坐标都为偶数的像素设为背景、其余设为
同色，即可同时达到两个方向的上界；回归测试覆盖此含孔图案。

一条长度 L≥1 的 chord 两侧有 2L 个同色像素，两个凹角端点外侧还各需要一个不同的同色像素，
所以每个有 chord 的颜色至少占 4 个像素。不同颜色不能共享像素，颜色组数至多 4096/4=1024。
这只是安全上界，不声称 1024 组可以同时达到。

每条冲突边对应一个内部整数格点，每个格点最多承载一条水平和一条垂直 chord，故 E≤63²。
HKDW 的队列和显式 DFS 栈至多占一侧的顶点数；允许重复的最短层根长度至多为 E。

因此空间仍为 O(n²)，时间仍为 O(n³)。没有实施索引压缩、跨阶段存储复用或其他匹配优化。

## 栈预算

本次 x86_64 构建的 `size_of::<SparseOptimalScratch64>()` 为 **482,032 字节，约 470.7 KiB**。
此前对象与预分配堆缓冲合计 790,838 字节；减少约 39%，初始化分配次数从 40 次降为 0。
Rust 默认布局、指针宽度以及未来字段变化都可能改变对象大小，集成时可直接使用 `size_of` 核算。

对象大小不等于调用栈峰值。Debug 构建中，`Result` 的 `?` 展开、按值辅助函数和大对象临时副本
会增加栈占用；迁移前的测试辅助函数搬运方式曾触发栈溢出。示例、基准和 worker 测试均使用
直接 `new()` 加引用传递。兼容 `Result` 构造入口通过直接模式匹配验证；使用它的旧调用方
应改用 `new()`，或另行核算完整调用链的栈预算。

资源回归在 debug 和 release 下均验证了 4 个并发 worker，各自使用 2 MiB 栈，包含固定输入数组、
构造、含孔和棋盘格反复分解。这个数值是已验证的测试环境配置，不是任意调用链的栈峰值保证。
主线程和引擎线程池的栈大小由调用方环境决定，可参考
[Rust 线程栈文档](https://doc.rust-lang.org/std/thread/#stack-size)。

## 验证与性能边界

- 分配计数器按线程隔离，验证 `new`、`Default`、兼容构造入口、借用分解及析构零分配。
- 返回的矩形切片地址位于 scratch 对象范围内。
- 4096 个输出矩形、两侧 1953 条 chord、3969 条冲突边／重复根和长 DFS 路径的边界检查。
- 672 种四像素颜色组、含孔彩色区域、空输入、非法重叠输入及重复使用。
- 原有 65,536 个 4×4 二分图穷举和 6,304 张图片的两种表示差分检查。

栈存储的确定收益是消除内部堆分配并缩减容量，不保证所有输入单线程加速。数组需要完整初始化，
因此应按 worker 复用，而不是每张图重新构造。定核对比中，初始化加销毁约从 5.1 μs 变为
6.7 μs；整图热路径依输入有涨有跌，规则彩色块约慢 10%。多线程分配器竞争的实际收益需在
调用方体素引擎中测量。
